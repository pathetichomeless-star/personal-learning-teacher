## 4. MANDATED PROOF — wire_rate_excess_frames_max ≤ 1 from the media-epoch definition (A.5)

Let M = MEDIA_FRAME_MS = 20 and fix one epoch with anchor e (= media_epoch at its creation).

**Invariant (I):** every send belonging to this epoch with in-epoch index j (0-based) starts at s_j ≥ d_j := e + j·M.
- *Base (j=0).* E1/E4: e = monotonic_now() at pacer start; the pacer loop computes not_before = max(deadline_0, normal_floor, send_guard_until) and proceeds only after a re-checked wait with monotonic_now() ≥ not_before ≥ d_0; the send is issued after the epoch exists, so s_0 ≥ e = d_0. E2: the preserved head is re-indexed j=0 with deadline_0 = e := now ⇒ s_0 ≥ now = e. E3: e := C + M (C = completion of the slow send); the next send must satisfy BOTH next_deadline = C + M and send_guard_until = C + 15 < C + 20, so the deadline binds ⇒ s_0 ≥ C + 20 = e. In all four creations s_0 ≥ d_0.
- *Step.* Within an epoch the deadline sequence is never re-anchored (E2/E3 create a NEW epoch, so they cannot fire inside one); the wait condition with re-check applies identically to frame n+1 ⇒ s_{j+1} ≥ d_{j+1}. The 15 ms floor and send_guard_until only raise not_before, so they can delay but never advance a send; hence they cannot violate (I).

**Theorem.** At an evaluation point t = s_j (the doc correctly reduces the max to send starts: sent_in_epoch is a right-continuous step function, constant between send starts, while permitted is non-decreasing ⇒ wire_excess is non-increasing between send starts ⇒ its epoch maximum is attained at an evaluation point), sent_in_epoch(t) = j+1. From (I): e + jM ≤ s_j = t ⇒ jM ≤ t − e ⇒ j ≤ ⌊(t − e)/M⌋ (j integral) ⇒ j+1 ≤ 1 + ⌊(t − e)/M⌋ = permitted(t). The max(0,·) is vacuous in-domain (t ≥ s_0 ≥ e ⇒ permitted ≥ 1 > 0), retained as written without behavioural effect. Therefore wire_excess(t) ≤ 0 at every evaluation point of every epoch, hence **wire_rate_excess_frames_max ≤ 0 ≤ 1**. ∎

- Tightness: a send exactly on its deadline (s_j = e + 20j) attains excess 0 (confirmed numerically); the single frame between the proven ≤ 0 and the PO gate ≤ 1 is pure headroom, as A.5 states.
- Boundary behaviour: E1/E4 — "can only be late, never early" preserves (I) with slack; E2 — the preserved head becomes frame 0 with deadline_0 = now, and the connection-wide 15 ms floor can only postpone it; E3 — the armed guard (C+15) is strictly below the deadline (C+20), so the deadline binds and (I) holds; no overshoot credit or debt crosses any boundary because sent_in_epoch := 0 and permitted re-anchors simultaneously.
- The scenario that broke the rev-7 anchor: with the anchor at the first observed send, a compliant pacer whose first frame lands Δ ∈ (20,40] ms past its true deadline (pacer-start delay) is measured against a shifted clock while its next send obeys the true deadline — under an anchor-at-first-send definition the legal recovery pair (s_0 = e+35, s_1 = e+50) already reads sent=2 vs permitted=1 (excess 1, accumulating under continued catch-up), which is the falsification class rev-7 suffered. Under the rev-8 epoch definition the same pair reads permitted(e+50) = 3 ⇒ excess −1 (verified numerically; attack 8). The overshoot is absorbed by the media clock's own allowance and cannot be double-charged. I note for transparency: I did not read the rev-7 review text (independence rules), so the doc's specific "ceil(Δ/20) = 2" characterization of rev-7 is inherited, not re-derived; what I prove and verify is that the rev-8 definition yields ≤ 0 on all these scenarios.
- Residual risk examined: a non-pacer send path would break (I) and be caught by the gate (its purpose); the single-pacer rule (active_pacer_tasks_max ≤ 1) plus the post-terminal tripwire close that hole.

## 6. FINDINGS

**BLOCKERS**

- **B-1 (epoch-creation list contradicts the initialization block and the PO; false-FAILs the wire gate on every multi-response run).** Anchor: A.5 "E4 — pacer restart after cancel/stall" vs A.5 initialization "at every pacer start: media_epoch = monotonic_now(); frame_index = 0; pacer_starts += 1" vs §0.8.1 M1 "E4 pacer restart" and PO M1 "pacer restart creates a new epoch". Falsification: the standard flow is pacer drains response 1 normally (A.9 steps 4-6), exits, and _ensure_pacer starts a new task for response 2. Under the letter of A.5 this start is not E1 (not the connection's first task), not E2/E3, and — per the "after cancel/stall" qualifier — not E4, so sent_in_epoch and epoch_ordinal are not reset; yet the initialization block re-anchors media_epoch := now. Evaluation at response 2's first send start: sent_in_epoch = 501 (say), permitted = max(0, 1 + ⌊0/20⌋) = 1 ⇒ wire_excess ≈ 500 ⇒ wire_rate_excess_frames_max ≫ 1 ⇒ NORMAL_LONG_RESPONSE_ACCEPTANCE false-FAIL on the primary acceptance scenario. (The alternative reading — one eternal pacer task that never exits after a normal drain — is untenable: §0.8.3 item 5 then converts every inter-response idle gap > 250 ms into a Case-B fatal stall flushing the NEW generation's first frames.) The E4 qualifier is a rev-8 drafting drift not present in the PO or §0.8.1 and not recorded as a merge decision. Minimal fix (one line): make E4 read "every pacer start other than E1" (restoring the PO's unqualified "pacer restart"); alignment with segments-never-span-epochs and the initialization block is then total. With that line, my proof in §4 covers E4 as stated.

**MAJORS**

- **M-1 (T2 window end can never fire on the common timing; cross-session contamination when it eventually does).** Anchor: A.12 T2 — "the window ends on the FIRST new pcm_fifo_drained_to_empty_events edge for THAT FIFO instance after the tts stop"; combined with A.9's ordering (the stop is emitted only after the pacer has drained/sent the backlog) and the client source (audio_codec.py:400 push on packet arrival; callback consumes in real time at 50 fps). Falsification: the bridge sends the last audio frame BEFORE emitting tts stop, so the client FIFO's final drain-to-empty pull frequently completes before the tts stop message is processed (FIFO residual is small and drains in ≤ a few 20 ms blocks; the stop arrives one network hop later). In that case no drained edge exists after the stop ⇒ the window never ends ⇒ row 18's scoped delta is never produced (acceptance capture hangs or is unevaluable) on what is arguably the majority timing. Worse: if the FIFO idles empty until the NEXT session's first push, the "first new edge after the stop" belongs to the next session's first chunk; if that chunk's pulls are partial (plausible at session start), the old window's partial_zero_pad delta absorbs the next session's samples ⇒ false FAIL of row 18.
